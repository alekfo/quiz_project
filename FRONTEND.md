# FRONTEND.md

Правила работы над внешним видом QuizApp. Читается перед любой фронт-задачей.
Фронтенд пишет Claude; бэкенд (`*.py`, миграции, настройки) пишет пользователь — см. «Граница с бэкендом».

Область действия: `templates/`, `*/templates/`, `static/css/`, `static/js/` (кроме `htmx.min.js`).

## Принятые решения (2026-10-01)

| Вопрос | Решение |
|---|---|
| Стили | Чистый CSS с переменными в `:root`. Без фреймворков, сборщиков, npm и CDN |
| Тема | Светлая и тёмная, переключение по системной настройке (`prefers-color-scheme`) |
| Адаптив | Mobile-first: базовые стили — под телефон, расширение через `@media (min-width: …)` |
| Характер | Игровой, яркий: насыщенные цвета, крупные кнопки, скругления, заметные состояния |
| Классы | Как сейчас — kebab-case по смыслу блока (`.btn`, `.room-list`, `.question-form`). Не BEM |
| JavaScript | Существующие inline-`<script>` в шаблонах не трогать; новый общий код — файлами в `static/js/` |
| Подтверждения | Перед страницей Claude коротко описывает, что собирается сделать; после «да» правит файлы сам и показывает результат |
| Порядок | Токены и `base.html` → меню → списки и превью → формы → лобби → игра |

## Стек и ограничения

- Django Templates + HTMX 2 (`static/js/htmx.min.js`, локальный файл) + чистый CSS + ванильный JS.
- Один общий `templates/base.html`, от него наследуются все страницы.
- Стили — только в `static/css/`. Не inline и не в `<style>` внутри шаблонов.
  Исключение: honeypot в `users/register.html` спрятан inline-стилем намеренно.
- Шрифты и иконки — без внешних запросов (системный стек шрифтов, эмодзи или inline-SVG).
  Подключение веб-шрифта — отдельное решение, файлы тогда кладутся в `static/`.

## Дизайн-система

Значения выбраны 2026-10-02 на шаге «База», единственный источник — блок `:root` в `static/css/main.css`.
Палитра и общий вид утверждены пользователем после живой проверки главной (2026-10-02) — цвета не менять без запроса.
Новые цвета и размеры по страницам не вводить: сначала токен, потом использование.

Название продукта в интерфейсе — **QuizCrowd** (логотип в шапке, заголовок вкладки по умолчанию).

Контраст всех пар «текст / фон» из таблицы посчитан: не ниже 4.8:1.

### Токены

Все цвета, отступы, радиусы, тени и размеры шрифта — CSS-переменные в `:root`. В правилах компонентов —
только `var(--…)`, без «голых» значений.

- **Цвета — по роли, а не по оттенку**: фон страницы, фон поверхности (карточки), основной текст, приглушённый текст,
  граница, акцент, акцент при наведении, текст на акценте, успех, ошибка, предупреждение.
- **Тёмная тема** — те же переменные, переопределённые в `@media (prefers-color-scheme: dark)`.
  Компоненты о теме не знают. Ручного переключателя пока нет.
- **Отступы** — одна шкала (шаг 4px), **радиусы** и **тени** — по 2–3 значения.
- **Типографика** — шкала размеров, базовый размер текста не меньше 16px (на телефоне меньше — нечитаемо,
  а поля ввода с меньшим шрифтом iOS зумит).

### Характер: игровой, яркий

- Один насыщенный акцентный цвет плюс цвета состояний (верно / неверно / ожидание).
- Крупные кнопки и варианты ответа: высота области нажатия не меньше 44px.
- Заметные скругления, чёткие состояния `hover` / `focus-visible` / `active` / `disabled`.
- Анимации — короткие и по делу (нажатие, появление результата); уважать `prefers-reduced-motion`.
- Контраст текста и фона — не ниже 4.5:1 в обеих темах.

### Адаптив

- Базовые стили — для ширины от 360px, одна колонка.
- Брейкпоинты — только там, где раскладка реально меняется (ориентир: 640px и 1024px).
- Никакого горизонтального скролла страницы; широкие таблицы и списки прокручиваются внутри своего блока.
- Для mobile-first в `base.html` нужен `<meta name="viewport" content="width=device-width, initial-scale=1">` —
  сейчас его нет, добавляется на первом шаге. Там же `lang="en"` → `lang="ru"`.

### Компоненты

Каждый компонент — один класс и модификаторы отдельными классами (`.btn`, `.btn-primary`, `.btn-danger`).
Перед созданием нового класса — проверить, нет ли подходящего в `static/css/main.css`.

Базовый набор: кнопка (обычная / главная / опасная / disabled), карточка, поле формы с подписью и ошибкой,
flash-сообщение (`.messages li.success` / `.error`), список, шапка, таймер, спиннер, вариант ответа.

Готово (2026-10-02):

- **Кнопка** — `.btn` и модификаторы `.btn-primary` (главное действие), `.btn-danger`, `.btn-ghost` (без рамки и фона);
  `:disabled` / `aria-disabled="true"`. Иконка внутри кнопки — `<svg class="btn-icon">`.
- **Карточка** — `.card`.
- **Поля форм** — оформлены по тегам (`input`, `select`, `textarea`, `label`, `.errorlist`, `.helptext`),
  отдельный класс не нужен: `{{ form.as_p }}` выглядит оформленным на любой странице.
- **Тосты** — `.messages li` + класс уровня (`success` / `error` / `warning` / `info`, без класса — как `info`):
  прямоугольники в правом нижнем углу (на телефоне — во всю ширину у нижнего края), плавно исчезают через 15 секунд.
  Из JS — `QuizCrowd.showToast(text, level)`.
- **Шапка** — `.site-header`: логотип `.logo`, справа имя пользователя (`.header-user`, ссылка на профиль,
  скрыто уже 480px) и «Выйти».
- **Разделы** — `.site-nav` с пунктами `.nav-item` (`.nav-icon` + `.nav-label`, текущий раздел — `.is-active`).
  От 640px — узкая панель слева, название выезжает справа от иконки при наведении и фокусе.
  На телефоне — список под шапкой, открывается бургером. Виден только залогиненному. Иконки — inline-SVG.
- **Метка** — `.tag` (категория и подобное); **пустое состояние списка** — `.empty-state`.
- **Карточка квиза** — `.card.quiz-card` в сетке `.quiz-grid` (1 / 2 / 3 колонки на 0 / 640 / 1024px):
  `.tag`, `.quiz-card-title` со ссылкой `.quiz-card-link`, `.quiz-card-description` (обрезка до двух строк),
  `.quiz-card-author`, `.quiz-card-meta`. Вся карточка — область нажатия `.quiz-card-link` (растянутый `::after`);
  другие ссылки внутри карточки должны иметь `position: relative; z-index: 1`, иначе по ним не кликнуть.
  Использовать эту же карточку в списках квизов (шаг 3).
- **Блок приветствия** — `.hero` + `.hero-text` + `.hero-actions` (ряд кнопок с переносом).

### Организация CSS

- Пока один файл `static/css/main.css`: токены → сброс и базовые теги → компоненты → страницы.
- Разбивать на несколько файлов — когда станет неудобно, по согласованию.
- Существующие классы не переименовывать без причины; неиспользуемые — удалять только убедившись поиском
  по шаблонам и `*.py`, что на них ничего не ссылается.

## Контракты с бэкендом — не ломать

Менять внешний вид и структуру разметки можно свободно. Перечисленное ниже нельзя переименовывать,
удалять или переносить без согласования: на это завязаны вьюхи, JS, HTMX или WebSocket.

### Общее

- В каждой `<form method="post">` — `{% csrf_token %}`.
- `name` полей, `action` и `method` форм не менять. Поля рендерить через объекты формы Django
  (`{{ form.field }}`, `{{ form.field.errors }}`), а не писать `<input>` вручную.
- Действия, меняющие данные, — только `<form method="post">` + `<button>`, не `<a href>`
  (вьюхи закрыты `require_POST`, ссылка даст 405).
- Имена маршрутов в `{% url %}` и имена переменных контекста не менять.
- Не добавлять в шаблоны логику доступа: что показывать, решает контекст из вьюхи.
- Атрибут `hidden` — рабочий механизм показа/скрытия блоков из JS. Не перебивать его
  CSS-правилом вида `display: flex` на том же элементе без `[hidden] { display: none }`.

### `templates/base.html`

- `<ul class="messages">` внутри `.container-header-messages` — рендерится всегда, даже пустой:
  в него пишут `base.js` (`showToast`) и кнопка копирования ссылки в `room_detail.html`
  (она ищет `.messages`, а при отсутствии создаёт его в `.container-header-messages`).
- Подключение `static/js/base.js` — в `<head>` **без `defer`**: скрипт ставит класс `.js` на `<html>` до отрисовки
  (без JS список разделов на телефоне виден всегда, с JS — только по бургеру). После него — `htmx.min.js`.
- `#nav-toggle` (бургер, `aria-controls="site-nav"`, `aria-expanded`) и `#site-nav` (класс `.is-open`) — связка для `base.js`.
- Подсветка текущего раздела — по `request.resolver_match.namespace` / `url_name` в шаблоне; при добавлении нового
  приложения или раздела условие в `base.html` нужно дополнить.
- `.header-main` — общий «ряд с разнесёнными краями», используется и в шапке, и в `room_detail.html`;
  стили шапки вешать на `.site-header .header-main`, а не на сам класс.
- Блоки `{% block title %}` и `{% block body %}`.
- Форма выхода и форма «Связаться с поддержкой» — POST-формы, остаются формами.

### `static/js/base.js`

Общий код всех страниц (вынесен из inline-скриптов `base.html` 2026-10-02 по согласованию):

- `QuizCrowd.showToast(text, level)` — показать тост; удаление через 15.5 с (событие `animationend` анимации
  `toast-out` + таймер-страховка, если анимация не проигралась). Имена анимаций `toast-in` / `toast-out` в `main.css`
  не переименовывать.
- Обработчик `htmx:responseError` — красный тост вместо `alert()`.
- Бургер разделов: клик переключает `.is-open` и `aria-expanded`, `Esc` закрывает.

### Главная — `quizzes/quizzes_menu.html`

- Контекст из `quizzes.views.menu`: `rooms` (активные комнаты пользователя, только залогиненному) и
  `showcase_series` — до 12 серий витрины; у каждой — аннотации `rounds_count` и `like_count`,
  `category` и `user` подгружены через `select_related`.
- Страница открыта гостю: карточки ведут на превью, которое требует входа, — гость попадёт на логин с возвратом.

### HTMX-partial'ы — `social/templates/social/`

- `_like_button.html` — корневой элемент `.like-block`; `_follow_button.html` — корневой `.follow-block`.
- Корневая обёртка обязана оставаться единственным корнем partial: вьюха возвращает его целиком,
  HTMX заменяет через `hx-target="closest .…-block"` + `hx-swap="outerHTML"`.
- Атрибуты `hx-*` и дублирующий `action` (fallback без JS) не убирать.
- Образец для новых кнопок такого рода — раздел «HTMX-паттерн для кнопок-действий» в `quiz_project_plan.md`.

### Фрагменты, приходящие по WebSocket

`multiplayer/_room_status.html` (корень `#room-status`) и `gameplay/_players_status.html` (корень `#waiting-info`)
рендерятся в консьюмерах через `render_to_string` **без `request`** и заменяют элемент целиком.

- Корневой элемент и его `id` сохранять.
- Внутри этих фрагментов нельзя использовать `request`, `user`, `{% csrf_token %}` и формы —
  их там нет, отрисуется пустота. Формы лобби лежат в `room_detail.html` вне `#room-status`.
- `gameplay/_series_progress.html` включается и в лобби, и в `solo_room.html` — править с оглядкой на оба места.

### Формсет вопросов — `quizzes/quiz_form.html`

- `{{ question_formset.management_form }}`, `#question-list`, `#add-question-btn`,
  `<template id="empty-question-template">`, `.question-form`, `.delete-question-btn`.
- Чекбокс `DELETE` остаётся в DOM: при «удалении» вопроса блок скрывается, а не удаляется.
- Тот же подход (management form + поля формсета) — в `ai_generator/temp_ai_quiz.html`.

### Игра — `gameplay/play.html`

- `#answer-form`, `input[name="chosen_option_id"]`, `#submit_button`, `#timer`, `#fact`, `#waiting-info`.
- Таймер и блокировка отправки управляются inline-JS страницы — его не трогать.

### Лобби — `multiplayer/room_detail.html`, `_room_status.html`

- `#confirm-ready-form`, `#select-series-form`, `#reset-series-form`, `#start-form`, `#start-button`,
  `#ready-confirmed-msg`, `#room-link`, `#copy-link-btn`.
- `.toggle-btn` + `data-target="<id блока>"` + `hidden` у целевого блока
  (`#link-container`, `#series-history-container`).

### Регистрация — `users/register.html`

- `#submit-btn`, чекбокс `privacy_policy`.
- Honeypot-поле `website` должно оставаться в разметке и быть невидимым для человека.

## Граница с бэкендом

- Если задаче нужна правка в `*.py` (новая переменная контекста, новый URL, partial-ответ вьюхи) —
  Claude не правит сам: останавливается, описывает, что нужно, пользователь делает.
- Вынос существующего inline-JS в файлы, переименование id/классов из раздела «Контракты» —
  только по отдельному согласованию.
- Коммиты и пуши делает пользователь.

## Порядок работы над страницей

1. Прочитать шаблон и найти его зависимости: JS, HTMX, WebSocket, разделы «Контрактов» выше.
2. Коротко описать пользователю, что будет сделано; дождаться «да».
3. Сверстать: сначала узкий экран, затем расширение.
4. Открыть в браузере, сделать скриншоты: телефон и десктоп, светлая и тёмная тема.
5. Пройти руками сценарий страницы: форма отправляется, ошибки формы видны, HTMX-кнопки и
   live-обновления работают.
6. Показать результат. Новое решение по дизайну (токен, компонент) — дописать в этот файл.

Одна страница или один компонент за раз, в отдельной ветке.
