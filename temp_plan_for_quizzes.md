# План: «Сохранить квиз к себе» (завершение ветки `start_social`)

Составлен 2026-10-01. Временный файл — после реализации перенести итог в `CLAUDE.md` / `quiz_project_plan.md` и удалить.

## Цель

1. На профиле пользователя (`user_detail.html`) — список его публичных квизов (`QuizSeries`).
2. Чужой публичный квиз можно «сохранить к себе».
3. В списке квизов (`quizseries_list.html`) — две секции: «Мои квизы» и «Добавленные».
4. В мультиплеере хост выбирает серию по правилу «я автор или сохранил к себе» (сейчас — «я автор или публичная»).

## Принятые решения

| Вопрос | Решение |
|---|---|
| Автор сделал серию приватной | **Строки не удаляются.** Фильтр при чтении: сохранённая серия показывается и доступна, только пока она `public`. Вернули публичность — появилась снова |
| Имя модели | `SavedQuizSeries`; в UI — «Сохранить к себе» / «Убрать» |
| Приложение | `social` (рядом с `QuizSeriesLike`) |
| Соло-запуск | Остаётся `visible_to`: любую публичную серию можно сыграть с превью, не сохраняя |
| Серия в комнате стала недоступна хосту | Ничего не делать, доиграть. Правило проверяется только в момент выбора серии |
| Где кнопка | Только на превью серии (`quizseries_preview.html`), рядом с лайком. На профиле и в списке кнопки нет |
| Свой профиль | Список своих серий не показывается (они и так в «Мои квизы») |
| Смена статуса существующей серии | Не в этой ветке. Сейчас статус задаётся только при создании (`quizzes/views.py:165`), вьюхи редактирования серии нет — менять можно только через админку |

## Три правила доступа — не путать

| Правило | Смысл | Где используется |
|---|---|---|
| `filter(user=user)` | я автор | детали, редактирование, удаление, секция «Мои квизы» |
| `visible_to(user)` | могу увидеть: публичные + свои | превью, соло-запуск, лайк, **сохранение к себе** |
| `available_to(user)` — новое | моя библиотека: свои + сохранённые публичные | выбор серии в комнате |

Секция «Добавленные» — это `available_to` без своих: сохранённые и сейчас публичные.

## Шаги

Бэкенд (шаги 1–3, 6 и вьюхи шагов 4–5) пишет пользователь. Шаблоны шагов 3–5 — зона Claude по `FRONTEND.md`,
после того как готов контекст из вьюх.

### Шаг 1. Модель `SavedQuizSeries` — `social/models.py`

- Поля: `user` → `AUTH_USER_MODEL` (`CASCADE`, `related_name="saved_series"`), `series` → `QuizSeries`
  (`CASCADE`, `related_name="saved_by"`), `created_at` (`auto_now_add`).
- `UniqueConstraint(fields=["user", "series"])` — по образцу `QuizSeriesLike`.
- Запрет «сохранить свою серию» на уровне БД не выразить (условие через FK на другую таблицу) — он будет во вьюхе.
- Миграция, регистрация в `social/admin.py` (`list_display` с FK + `list_select_related`, как у лайков).

### Шаг 2. `QuizSeriesQuerySet` — `quizzes/models.py`

Два метода рядом с `visible_to`:

- `saved_by_user(user)` — сохранённые пользователем и сейчас публичные (для секции «Добавленные»).
- `available_to(user)` — свои + `saved_by_user` (для комнаты).

**Ловушка — дубликаты строк.** Наивный вариант
`filter(Q(user=user) | Q(status="public", saved_by__user=user))` даёт `LEFT JOIN` на таблицу сохранений
без условия по пользователю: своя серия, которую сохранили N других людей, вернётся N раз. Варианты:

- `Exists`-подзапрос (рекомендую) — без JOIN, дубликатов нет:
  ```python
  saved = SavedQuizSeries.objects.filter(series=OuterRef("pk"), user=user)
  self.filter(Q(user=user) | (Q(status="public") & Exists(saved)))
  ```
  Чтобы `quizzes` не импортировал `social` на уровне модуля (циклический импорт), модель брать через
  `apps.get_model("social", "SavedQuizSeries")` или импортировать внутри метода.
- `.distinct()` поверх наивного варианта — проще, но ломается при последующем `order_by` по полям JOIN'а.

Для анонима оба метода возвращают `self.none()`.

Это единственное место, где `quizzes` узнаёт о `social`. Отступление от «quizzes — чистое хранилище»
осознанное: правило доступа к серии должно жить на её QuerySet, как `visible_to`.

### Шаг 3. Сохранение и удаление — `social/`

- `social/urls.py`: `series/<int:series_id>/save` и `series/<int:series_id>/unsave`.
- `save_series`: `@login_required` + `@require_POST`; серия — через `get_object_or_404(visible_to(user), pk=...)`;
  своя серия (`series.user_id == user.id`) → `PermissionDenied`; `get_or_create`.
- `unsave_series`: серия — через `visible_to(user)`, симметрично `save_series` и `delete_like`
  (решение пользователя, изменено по ходу реализации). Следствие: сохранённую серию, ставшую приватной,
  убрать у себя нельзя (404) — строка остаётся в БД, но нигде не показывается из-за фильтра при чтении
  и снова появится, если автор вернёт публичность.
- `social/services.py`: `get_save_context(cur_user, series)` → `series`, `already_saved`, `is_my_series`.
- Ответ — по HTMX-паттерну из `quiz_project_plan.md`: `_is_htmx` → partial `social/_save_button.html`, иначе redirect на превью.
- Partial `_save_button.html` — обёртка `.save-block`, кнопка не рендерится, если `is_my_series`.
- `QuizPreviewView.get_context_data` — добавить `context.update(get_save_context(...))`; в `quizseries_preview.html` —
  `{% include "social/_save_button.html" %}` рядом с лайком.

## Проверка вживую

Два пользователя: A (автор), B.

1. A создаёт публичную и приватную серии. B открывает профиль A → видит только публичную.
2. B открывает превью публичной → «Сохранить к себе» → кнопка меняется без перезагрузки; повторный клик — «Убрать».
3. У B в списке квизов серия в секции «Добавленные», с автором; у A в «Добавленных» пусто, своя — в «Мои квизы».
4. A открывает превью своей серии → кнопки сохранения нет. Прямой POST на `save` своей серии → 403.
5. B: POST на `save` приватной серии A по подобранному `pk` → 404.
6. Комната B: в выборе серии — свои и сохранённая; несохранённой публичной серии A нет.
   Подставить её `pk` в POST вручную → форма отклоняет.
7. Через админку сделать сохранённую серию приватной → у B она пропала из «Добавленных» и из выбора в комнате;
   вернуть `public` → появилась снова.
8. Серию A сохранили два пользователя → у A в «Мои квизы» и в выборе комнаты она одна, без дублей (проверка шага 2).
9. Комната с уже выбранной серией, затем серия стала приватной → раунды доигрываются.
10. Без JS: сохранение работает через обычный POST и редирект.

## Вне этой ветки

- Редактирование серии (смена статуса, названия) в UI.
- Каталог публичных серий — после шага 6 найти чужую серию можно только через профиль автора.
- Счётчик «сохранили N раз», кнопка «Убрать» прямо в списке.
- Клонирование серии («забрать копию навсегда») — сейчас сохранение это ссылка: автор изменил или удалил
  раунды — у сохранившего тоже изменилось.
- Пагинация списков серий на профиле и в «Добавленных».
