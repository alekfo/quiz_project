# CLAUDE.md

## Режим работы с пользователем

**Важно: пользователь пишет этот проект сам.** Claude в этом репозитории выступает в роли технического консультанта/senior-инженера, к которому обращаются за советом — не как исполнитель, который сам пишет код и делает коммиты.

- По умолчанию **не пиши код и не редактируй файлы**, пока пользователь явно не попросит внести конкретное изменение.
- На вопросы вида "как лучше сделать X", "куда это положить", "правильно ли я делаю Y" — отвечай как консультация: рекомендация + обоснование + альтернативы/trade-off'ы, без немедленной реализации.
- Если пользователь просит именно написать/поправить код — это исключение из общего режима, делай это как обычно.
- Не бери на себя архитектурные решения самостоятельно — предлагай варианты, финальный выбор за пользователем.

## О проекте

**QuizApp** — платформа для создания и прохождения викторин с AI-генерацией вопросов (Claude API), соло и мультиплеер-режимами, соцфункциями (подписки, лайки, челленджи) и монетизацией.

Полный план — в [`quiz_project_plan.md`](quiz_project_plan.md): стек, структура папок, модели, сценарии использования, этапы разработки.

### Стек
Django 5 (sync) + PostgreSQL + Redis + Celery + Django Channels (WebSocket) + HTMX + Anthropic Claude API. Деплой — Hetzner/DigitalOcean (Frankfurt), Gunicorn + Nginx.

### Ключевое архитектурное правило
Приложение `ai_generator` зависит от `quizzes` (импортирует его модели, чтобы сохранять сгенерированные викторины), но не наоборот. `quizzes` — чистое хранилище/отображение (`Quiz`, `Question`, `AnswerOption`), не знает, создана ли викторина вручную или через AI. Форма параметров AI-генерации (тема, кол-во вопросов, сложность, стиль) размещается в `ai_generator`, а не в `quizzes`. Подробности — в разделе "Правило взаимодействия quizzes ↔ ai_generator" в плане.

### Текущее состояние (на момент последнего обновления этого файла — 2026-07-24)

- Django-проект `quiz_project` инициализирован: `settings.py`, `urls.py`, `asgi.py`, `wsgi.py` (пока единым файлом, план предполагает разбивку на `settings/base|development|production.py`). Фактически установлен Django 6.0.7 (план/этот файл раньше упоминали Django 5 — не критично, но при апгрейде плана стоит поправить).
- Создано приложение `users`: кастомная модель `User(AbstractUser)` (`email` unique, `ai_quizzes_generated`, `ai_quizzes_limit_per_day`, `is_subscribed`, `is_premium`, `email_confirmed`, `subscription_expires_at`). `AUTH_USER_MODEL = 'users.User'`. Важно: кастомная модель пользователя должна существовать до первого `migrate` в проекте — если БД уже проинициализирована со стандартным `auth.User`, при подключении кастомной модели ловите `InconsistentMigrationHistory` (уже наступали на это, чинится пересозданием БД на dev-окружении).
- Приложение `quizzes` — модели реализованы (не заглушки): `Category` (`title`, `name`), `Quiz` (`user`, `title`, `description`, `type` — ai/by_user, `category` FK `on_delete=PROTECT`, `subject`, `level`, `style`, `status` — default `private`, `created_at`), `Question` (`quiz`, `text`, `order`, `fact`), `AnswerOption` (`question`, `text`, `is_correct`, `order`).
- Приложение `ai_generator` реализовано: `GenerationRequest` (параметры генерации + `category` FK + `result` JSONField + `status`), `GenerationRequestForm`, `QuestionForm`/`QuestionFormSet` (formset для редактирования вопросов перед сохранением), `prompts.py` (`generate_quiz_questions()` — запрос к Claude через HTTP-прокси), `views.index()` (генерация + рендер формы на правку) и `views.save()` (сохранение через `quizzes.services.create_quiz_from_any_data`).
- Реализован flow AI-генерации: пользователь заполняет параметры → `index()` синхронно (без Celery — отличие от сценария в плане, Celery ещё не подключён) вызывает Claude → результат сохраняется в `GenerationRequest.result` и в БД создаётся сама `GenerationRequest` → пользователь получает `formset` с вопросами на `temp_ai_quiz.html`, редактирует → сабмит на `save()` → `quizzes/services.py` создаёт `Quiz`/`Question`/`AnswerOption`.
