## 1. Что решили

Сейчас `/users/` показывает всех зарегистрированных пользователей. Так быть не должно.

| Вопрос | Решение |
|---|---|
| Что показывать по умолчанию | Только тех, на кого подписан текущий пользователь («Подписки») |
| Как найти остальных | Поиск на той же странице, параметр адреса `q`: `/users/?q=але` |
| По чему искать | Ник, имя, фамилия (`icontains`). **Не почта** — иначе по ней можно проверять, зарегистрирован ли человек |
| Минимальная длина запроса | 2 символа. Короче — показываются подписки и подсказка «Введите хотя бы 2 символа», без ошибки |
| Себя в результатах поиска | Нет |
| Лимит результатов | 20, сортировка по нику |
| Подписчики | Вторая вкладка «Подписчики» рядом с «Подписки» (кто подписан на меня) |
| Кнопка подписки в строке списка | Не делаем. Подписка — со страницы профиля |
| Живой поиск | HTMX поверх обычной GET-формы; без JS форма работает как обычная |

## 2. Что такое `q`

`q` — имя GET-параметра. В форме поиска поле называется `name="q"`, форма отправляется методом GET, поэтому
браузер не шлёт тело запроса, а дописывает значение в адрес: ввели «але» → `/users/?q=але`.

- URL и вьюха те же самые (`users:users_list`). Вьюха читает `request.GET.get("q", "")` и решает, что отдать:
  подписки или результаты поиска.
- CSRF-токен не нужен: поиск ничего не меняет.
- Ссылкой с `?q=` можно поделиться, кнопка «назад» возвращает к подпискам.

### Шаг 2. Константы рядом с `_REGISTER_RATE_LIMIT`

```python
_SEARCH_MIN_LENGTH = 2   # короче - поиск не выполняется
_SEARCH_LIMIT = 20       # максимум результатов поиска
```

### Шаг 3. `UsersListView`

Набросок (имена можно менять, но тогда сообщить Claude — на них завязан шаблон, см. раздел 4):

```python
class UsersListView(LoginRequiredMixin, ListView):
    """Страница «Пользователи»: мои подписки и подписчики, поиск по ?q=."""

    template_name = "users/users_list.html"
    context_object_name = "users"

    def get_template_names(self):
        # HTMX-запрос (живой поиск) получает только список, без шапки и панели разделов
        if self.request.headers.get("HX-Request") == "true":
            return ["users/_user_rows.html"]
        return [self.template_name]

    def get_queryset(self):
        User = get_user_model()
        self.q = self.request.GET.get("q", "").strip()
        self.is_search = len(self.q) >= _SEARCH_MIN_LENGTH

        if self.is_search:
            return (User.objects
                    .filter(Q(username__icontains=self.q)
                            | Q(first_name__icontains=self.q)
                            | Q(last_name__icontains=self.q))
                    .exclude(pk=self.request.user.pk)
                    .order_by("username")[:_SEARCH_LIMIT])

        # без запроса - те, на кого я подписан
        return (User.objects
                .filter(followers__follower=self.request.user)
                .order_by("username"))

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)
        context["q"] = self.q
        context["is_search"] = self.is_search
        if not self.is_search:
            context["followers"] = (get_user_model().objects
                                    .filter(following__following=self.request.user)
                                    .order_by("username"))
        return context
```

### На что обратить внимание

- **Убрать с класса `model = get_user_model()` и `ordering = ['username']`**: `get_queryset()` переопределён целиком,
  эти атрибуты больше не читаются. Сортировка задана явно в каждой ветке.
- **Направление связей** (легко перепутать): у `Follow.follower` — `related_name="following"`,
  у `Follow.following` — `related_name="followers"`.
  - на кого подписан я: `filter(followers__follower=я)`;
  - кто подписан на меня: `filter(following__following=я)`.
- **`.strip()`** обязателен: иначе запрос из двух пробелов считается поиском и вернёт всех.
- **Срез `[:_SEARCH_LIMIT]` — последним**, после `order_by`: после среза queryset нельзя фильтровать и сортировать.
- **`self.q` / `self.is_search` выставляются в `get_queryset()`**, а читаются в `get_context_data()` — в `ListView`
  `get()` вызывает их именно в этом порядке. Если хочется надёжнее — вычислить оба в `setup()` или `dispatch()`.
- **Дублей не будет**: `UniqueConstraint(follower, following)` гарантирует одну строку `Follow` на пару,
  JOIN не размножает пользователей. `distinct()` не нужен.
- **Проверка заголовка `HX-Request`** дублирует `_is_htmx` из `social/views.py`. Варианты: оставить строкой во вьюхе
  (проще) или вынести хелпер в общее место, например `quiz_project/` (один источник). Выбор за пользователем.
- **Partial `users/_user_rows.html` создаёт Claude** на шаге фронтенда. Пока его нет, HTMX-ветка упадёт
  с `TemplateDoesNotExist`; обычный запрос работает. Поэтому до фронта проверять только обычным GET.
- **Аватар**: строки списка выводят `user.avatar` — это поле самой модели, дополнительных запросов и
  `select_related` не нужно.
- `followers` при поиске в контекст не кладётся — шаблон вкладки при `is_search` не показывает.
  Почту в шаблон не выводим, во вьюхе ограничивать поля не требуется.

### Что проверить самому до передачи на ревью

- `/users/` — только подписки, сортировка по нику.
- `/users/?q=<часть ника>` — находит; себя в результатах нет.
- `/users/?q=<имя>` и `/users/?q=<фамилия>` — находит.
- `/users/?q=а` и `/users/?q=%20%20` — показываются подписки, а не результаты.
- `python manage.py test` — см. раздел 5: один существующий тест упадёт, это ожидаемо.

## 4. Контракт для фронтенда

| Что | Значение |
|---|---|
| Параметр адреса | `q` |
| `users` | Список для показа: результаты поиска (`is_search`) или мои подписки |
| `q` | Введённая строка после `strip()` — возвращается в поле и в текст «по запросу „…“» |
| `is_search` | `True`, если показаны результаты поиска |
| `followers` | Кто подписан на меня; только когда `is_search` ложно |
| HTMX-запрос | Тот же контекст, шаблон `users/_user_rows.html` |

Случай «один символ» отдельной переменной не требует: в шаблоне это `q and not is_search`.

## 6. Фронтенд (Claude, после зелёных тестов)

По правилам `FRONTEND.md`: перед вёрсткой — короткое описание и «да», затем правки и проверка в браузере.

- **`users/users_list.html`**
  - заголовок `.page-header` «Пользователи» с подписью;
  - форма поиска: `method="get"`, поле `type="search" name="q"`, кнопка «Найти»; поверх — HTMX

  - `is_search`: заголовок «Результаты по запросу „q“» и строки; пусто — «Никого не нашли по запросу „q“»;

    пустые состояния — «Найдите авторов через поиск» и «На вас пока никто не подписан»;
  - `q and not is_search`: подсказка «Введите хотя бы 2 символа»;

- **`static/css/main.css`** — компонент строки пользователя и поля поиска на существующих токенах;
