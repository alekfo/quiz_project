# QuizApp — Структура проекта и план разработки

## Стек технологий

| Компонент | Технология |
|---|---|
| Бэкенд | Django 5.x (синхронный) |
| База данных | PostgreSQL |
| Кэш / брокер | Redis |
| Фоновые задачи | Celery |
| Реальное время | Django Channels (WebSocket) |
| AI-генерация | Anthropic Claude API (claude-sonnet-4-5) |

| Веб-сервер | Gunicorn + Nginx |

## Основные модели

### users/
- **Profile** — аватар, bio, рейтинг, количество викторин, подписчики

### quizzes/
- **Category** — название темы (история, наука, спорт, кино...)
- **Quiz** — название, описание, автор, тип (AI / ручная), публичная/приватная, лайки, теги
- **Question** — текст вопроса, таймер, изображение (опционально)
- **AnswerOption** — варианты ответа, какой правильный, объяснение ответа

### ai_generator/
- **GenerationRequest** — параметры (тема, кол-во вопросов, сложность, стиль), статус задачи, результат

### gameplay/
- **GameSession** — пользователь, викторина, дата, итоговый счёт, время прохождения
- **PlayerAnswer** — ответ на конкретный вопрос, время ответа, правильно/нет

### multiplayer/
- **Room** — код комнаты, хост, статус (ожидание / игра / завершена), викторина
- **RoomPlayer** — участник комнаты, текущий счёт в реальном времени

### social/
- **Follow** — подписки между пользователями
- **QuizLike** — лайки на викторины
- **Invite** — приглашение в комнату по ссылке

## Правило взаимодействия quizzes ↔ ai_generator

Направление зависимости — только одностороннее: **ai_generator зависит от quizzes, но не наоборот.**

- **quizzes** — «хранилище» сущностей викторины (`Quiz`, `Question`, `AnswerOption`). Ничего не знает о том, как викторина была создана — вручную или через AI. Отвечает только за хранение, отображение, каталог, прохождение.
- **ai_generator** — весь процесс AI-генерации целиком:
  - форма с параметрами запроса (тема, кол-во вопросов, сложность, стиль) — размещается **здесь**, а не в quizzes;
  - модель `GenerationRequest` (статус задачи, параметры, результат);
  - Celery-задача, запрос к Claude API, промпты (`prompts.py`);
  - парсинг JSON-ответа и запись результата в модели quizzes (`ai_generator` импортирует `Quiz`/`Question`/`AnswerOption`, создаёт объекты).

Смысл разделения: AI-функциональность можно отключить/заменить, не трогая ядро (quizzes). Ручное создание викторины (Этап 2) — это форма и view в самом quizzes, поскольку не требует Celery/внешнего API.

## Сценарии использования

### AI-генерация викторины
```
Пользователь заполняет форму (тема, кол-во, сложность, стиль)
    → Django создаёт GenerationRequest в БД
    → Celery задача уходит в очередь
    → HTMX polling каждые 2 сек проверяет статус
    → Celery делает запрос к Claude API
    → Claude возвращает JSON с вопросами
    → Вопросы сохраняются в Quiz/Question
    → Пользователь видит готовую викторину
    → Публикует или оставляет приватной
```

### Ручное создание викторины
```
Форма создания викторины (название, категория, описание)
    → Добавление вопросов по одному
    → Превью викторины
    → Публикация
```

### Соло прохождение
```
Пользователь выбирает викторину
    → Создаётся GameSession
    → Вопросы показываются по одному с таймером
    → Каждый ответ сохраняется в PlayerAnswer
    → Итоговый экран с результатом и разбором ошибок
```

### Мультиплеер
```
Хост создаёт комнату → получает ссылку-приглашение
    → Друзья переходят по ссылке
    → Все видят лобби (Django Channels / WebSocket)
    → Хост запускает игру
    → Вопросы синхронно появляются у всех
    → Счёт обновляется в реальном времени
    → Итоговая таблица лидеров
```

### Социальный сценарий
```
Лента новых викторин от подписок
    → Лайк / комментарий
    → Вызов друга на викторину
    → Сравнение результатов
```

## Архитектура запросов

| Тип запроса | Решение |
|---|---|
| Обычные страницы (список, профиль, лента) | Django sync views |
| AI-генерация викторины | Celery + Redis |
| Мультиплеер реального времени | Django Channels (WebSocket) |
| Кэш повторных AI-запросов | Redis cache |

---

## Важные практики производительности

1. **select_related / prefetch_related** — избегать N+1 запросов к БД
2. **Кэш AI-результатов** — одинаковые запросы (тема + сложность + кол-во) отдавать из Redis
3. **Пагинация** — не отдавать все викторины сразу, по 20 штук
4. **Индексы в БД** — на полях по которым часто фильтруем (category, author, is_public)
