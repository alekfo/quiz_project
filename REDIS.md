# Redis на Windows через Docker Desktop — установка и запуск

Инструкция написана перед перезагрузкой машины (сессия от 2026-09-01), чтобы шаги не потерялись вместе с чатом. Нужен для Channel Layer будущего Django Channels (см. [`WS.md`](WS.md)) — сам переход на Channels ещё не реализован, это только подготовка инфраструктуры.

На момент написания на машине `docker --version` не находит команду — Docker Desktop ещё не установлен.

---

## 1. Установить Docker Desktop

1. Скачать инсталлятор: https://www.docker.com/products/docker-desktop/
2. Запустить установщик. На шаге конфигурации убедиться, что отмечено **"Use WSL 2 instead of Hyper-V"** (на Windows 11 обычно выбрано по умолчанию).
3. Если WSL2 ещё не включён на машине — установщик Docker Desktop обычно сам предложит его подтянуть. Вручную включить заранее можно командой (из PowerShell/терминала с правами администратора):
   ```
   wsl --install
   ```
4. **Перезагрузить машину** (тот самый шаг, ради которого пишется этот файл).
5. После перезагрузки — запустить Docker Desktop из меню Пуск. Дождаться в трее (нижний правый угол, значок кита) статуса "Engine running" — пока движок стартует, значок анимирован.

---

## 2. Проверить, что Docker работает

В любом терминале Windows (PowerShell, cmd, Git Bash — без разницы, CLI `docker` доступен из всех после установки):

```
docker --version
docker run hello-world
```

Второе — служебный тестовый контейнер: скачается, выведет приветственный текст и сразу завершится. Если прошло без ошибок — Docker настроен верно, можно переходить к Redis.

---

## 3. Запустить Redis

```
docker run -d --name redis -p 6379:6379 redis
```

Что означает каждый флаг:
- `-d` — фоновый режим (detached), не занимает терминал.
- `--name redis` — имя контейнера, чтобы обращаться к нему по имени, а не по случайному хэшу.
- `-p 6379:6379` — пробросить порт контейнера на `localhost` Windows-машины (первый `6379` — порт снаружи, второй — порт внутри контейнера).
- `redis` — официальный образ с Docker Hub, при первом запуске скачается автоматически (~ несколько десятков МБ).

Контейнер физически крутится в WSL2-VM (Linux), но порт `6379` виден с Windows-стороны как обычный `localhost:6379` — для `manage.py runserver`, запущенного нативно на Windows, это будет выглядеть как локально установленный Redis, без разницы в подключении.

---

## 4. Проверить, что контейнер поднялся и отвечает

```
docker ps
```
Должна быть строка с именем `redis`, статусом `Up ...` и портом `0.0.0.0:6379->6379/tcp`.

```
docker exec -it redis redis-cli ping
```
Ожидаемый ответ: `PONG`.

---

## 5. Управление контейнером в дальнейшем

- Остановить: `docker stop redis`
- Запустить снова (без пересоздания, данные — точнее, состав групп Channel Layer — не нужно сохранять между рестартами, см. ниже): `docker start redis`
- Посмотреть логи: `docker logs redis`
- Удалить совсем (если понадобится пересобрать с нуля): `docker rm -f redis`

Контейнер запущен **без** `-v` (volume) — данные не сохраняются между пересозданиями. Для роли Channel Layer это не проблема: группы/подписки WebSocket-соединений эфемерны по своей природе (соединение и так обрывается при рестарте сервера) — в отличие от гипотетического сценария, где Redis используется как кэш с данными, которые жалко терять.

## 6. Как это будет использоваться в проекте дальше

Когда дойдёт очередь до реализации Django Channels (см. [`WS.md`](WS.md), пока не реализовано), в `settings.py` появится:

```python
CHANNEL_LAYERS = {
    "default": {
        "BACKEND": "channels_redis.core.RedisChannelLayer",
        "CONFIG": {"hosts": [("localhost", 6379)]},
    },
}
```

Это уже отдельный шаг из реализации Channels, не из установки Redis самой по себе — на момент написания этого файла ещё не сделан.
